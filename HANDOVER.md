The handover notes for whoever picks this project up next. `README.md` is the player-facing and feature
reference. This file covers how the project is built, run, tested and deployed, where everything lives, and what is
still open.

## 1. What is in the box

A static site (`public/`) with a hub and four Three.js games, built on free CC0 asset packs: KayKit Adventurers 2.0,
Forest Nature, Fantasy Weapons Bits, Dungeon, Resource Bits and RPG Tools Bits, plus the Brackeys VFX bundle.

| Path | Game | Kind | Backend |
|---|---|---|---|
| `/` | **Game hub** | Launcher tiles over an orbiting forest scene | none |
| `/relic/` | **Forest Relic Hunt: Wildwood Colony** | Anno 1800-style colony builder with a third-person hero layer | none (localStorage save) |
| `/tactics/` | **Wildwood Tactics** | Turn-based squad tactics: roguelite campaign, skirmish vs AI, hot-seat, online duel | Supabase Realtime for online duels only |
| `/arena/` | **Wildwood Arena: Clash of Guilds** | Asynchronous build-and-raid game on the Tactics engine | Supabase Edge Function + Postgres (offline demo built in) |
| `/chess/` | **Wizard's Chess** | Full-rules 3D chess with battle animations and AI in a Web Worker | none |

There is no build step and no framework. The pages are plain ES modules. Three.js r170 is vendored in
`public/vendor/three` and resolved through an import map in each `index.html`.

## 3. Running locally

You need Node 20+ (CI uses 22) and Python 3, or any static file server.

```bash
cd public && python3 -m http.server 8123     # http://localhost:8123/
# or
npm start                                    # npx serve public
```

Useful URL flags:
- `/arena/?offline`: forces the in-browser "local cloud" (8 NPC guilds, same server code).
- `/tactics/?net=local`: two tabs on one machine can duel over BroadcastChannel.
- `/tactics/?offline`: disables online play.
- `/tactics/?join=CODE`: an invite link into an online duel room.

**Browser storage keys** (clear them to reset a game):

| Key | Used for |
|---|---|
| `wwc-save-v1` | colony autosave |
| `wildwood-tactics-run` | tactics campaign run |
| `wwt-autoend` | tactics "Auto end turn" toggle (`'0'` means off) |
| `wwt-tutorial-done` | tactics tutorial completed |
| `wildwood-arena-db` / `wildwood-arena-uid` | arena offline demo world + player |
| `wizchess-muted` | chess sound on/off |

## 4. npm scripts

| Command | What it does | When |
|---|---|---|
| `npm test` | All Node test suites, then `sync-shared --check` | Before every commit |
| `npm run sync` | Copies `tactics/src/{data,grid,battle}.js` and `arena/src/{economy,stronghold,server-core}.js` into `supabase/functions/_shared/` | **After editing any of those six files.** Otherwise `npm test` fails on the sync check |
| `npm run bundle` | sync + esbuild into `dist/arena-function.ts` | Only for dashboard (copy-paste) deploys |
| `npm run pack` | Rebuilds `public/assets/packs/*` | After adding or changing any model. Run `npm install` once first: the packing tools are devDependencies |

`node_modules/` is needed only for `npm run pack`. The games and tests run without it.

## 5. Architecture per game

### 5.1 Colony (`public/relic/src`)
- **Simulation:** `sim.js` is deterministic, fixed-step and DOM-free, with save/load as JSON. `map.js` handles
  seeded generation with fairness guarantees, and `data.js` holds all goods, buildings, tiers, relics and quests.
- **Rendering:**
  - `world3d.js`: terrain, water, an instanced forest in 24×24-tile chunks (culled), roads, fog/territory overlay, LOD
  - `kit.js`: builds every building from Dungeon/Resource/Tool pieces and merges the geometry per material, one
    baked model per building type
  - `units.js`: villagers, carriers, workers
  - `hero.js`: the Founder, creatures, raids, relics
  - `camera.js`: the RTS and hero cameras, touch gestures
- **UI and glue:** `ui.js` (HUD, build menu, inspector, minimap; DOM is touched only on change), `main.js`
  (input modes, day/night, VFX, autosave, quality auto-step-down below 36 fps), `ambience.js` (WebAudio).
- **Quality levels** (Low/Medium/High): pixel ratio, shadow map size and refresh rate, decor density, villager
  budget, view distance, low-poly far trees. Phones and 4-core machines start on Low.

### 5.2 Tactics (`public/tactics/src`)
- **Engine:** `battle.js` holds the turn flow, ability resolution and AI. It is deterministic: seed + squads +
  command log always give the same game. It renders through an awaitable `view` interface, and `NullView` runs it
  headless. The Arena server and online duels both rely on this determinism.
- **Supporting modules:**
  - `grid.js`: map generation, pathfinding, line of sight, cover
  - `data.js`: tiles, abilities, classes, items, guilds
  - `run.js`: campaign node map, loot, camp
- **`controller.js`:** input, HUD, hints and the threat overlay. It works for whichever sides are local
  (`localSides`) and applies remote commands. **Auto end turn:** `maybeAutoEnd()` runs after every local action.
  Once every living hero has acted (or none can still act), it shows a hint and calls `endTurn()` after 0.9 s
  (scaled by game speed). Selecting a hero, changing mode or pressing Esc cancels it. The tutorial guard can block
  it. The toggle is `#autoend` in the legend.
- **`view.js`:** the Three.js board, units, highlights, animations and the camp scene. **Camera framing:**
  `fitBoard(side)` searches the camera distance until all four board corners, at ground level and at unit height,
  project inside the free band between the HUD panels. It measures `#topbar`, `#roster`, `#legend`, `#hint`,
  `#unitpanel` and `#endturn`. It re-fits on resize until the player zooms, orbits or pans
  (`cam.fitted = false`). Pitch is 0.98 on landscape screens and 1.32 on portrait.
- **Other modules:** `net.js` (online duels, see §7.3), `tutorial.js` + `coach.js` + `help.js` (training grounds
  and help overlay), `main.js` (screens, modes, lobby).

### 5.3 Arena (`public/arena`)
- **`server-core.js`:** every authoritative action (register, save stronghold, upgrade, harvest, craft, scout, raid
  start/finish, leaderboard, season rollover, simulated defenses). It talks only to a small **store interface**:
  - `store-memory.js`: the browser offline demo and the tests. Optimistic concurrency via `_ver`.
  - `supabase/functions/_shared/store-supabase.js`: the cloud store. Optimistic concurrency via `updated_at`
    (`putProfileIf`).
- **Raid integrity:** `raidFinish` replays the submitted command log from the stored seed with the shared
  `battle.js`. Forged or illegal logs are rejected. `claimRaid` atomically flips the status column from `'open'`
  to `'done'` (the DB CHECK allows only those two values), so a raid settles once; `releaseRaid` reverts it on a
  failed replay. Harvest pays once under parallel calls.
- **Pure modules:** `economy.js` and `stronghold.js`. `main.js` is the UI, and `api.js` picks the cloud or local
  backend from `config.js`.

### 5.4 Chess (`public/chess/src`)
- `chess.js`: the rules engine, perft-verified.
- `ai.js` + `book.js` + `ai-worker.js`: opening book with 40+ master lines, positional evaluation, transposition table, multi-candidate selection, and alpha-beta with quiescence search in a Web Worker.
- `scene.js`: the hall, pieces and capture choreography.
- `vfx.js`: pooled particles, sprite sheets, debris, lightning, shake.
- `sfx.js`: the synth. `main.js`: flow and HUD.

### 5.5 Shared asset pipeline (`public/src/assets.js`, `actor.js`)
- `loadAssets` tries `assets/packs/<folder>.glb` first. Each pack is one meshopt GLB whose top-level nodes are
  named `@<original file>`, and the loader splits them back into `{ name: Object3D }` tables. If a pack is missing
  it falls back to the per-file originals in `assets/<folder>/`.
- Characters come from `packs/chars/*.glb`. Their skinned parts are merged into one mesh (`mergeCharacter`), so
  each actor is one draw call.
- Animations come from `packs/clips.glb`: both KayKit rigs are retargeted to a single skeleton (see the comment in
  `scripts/pack-assets.mjs` about the `_1` bone-renaming trap). Clips are created lazily on first use.
- Materials are shared per texture (`shareMaterials`, `sharedActorMaterials`). When disposing actors, dispose only
  what they own: see `disposeOwn` and `clearUnits` in `tactics/src/view.js`.

**Browser checks.** UI work was verified with ad-hoc Playwright scripts against `http://localhost:8123`. They

## 7. Supabase and deployment

### 7.1 Keys and secrets: read this first
- `public/arena/config.js` contains the project URL and the **publishable** key (`sb_publishable_…`). That key is
  public by design and is the only key that may ever be in the repo.
- **Never commit or paste the secret key (`sb_secret_…`) or the service-role key** anywhere in the repo, the
  workflow, or `config.js`. The Edge Function gets them from the Supabase platform environment automatically.
- A secret key was once pasted into a chat during development. It was never stored or used, but **rotate it in
  the Supabase dashboard** (Project Settings → API Keys) to be safe.

### 7.2 Arena backend
- **Schema:** `supabase/migrations/20261002000000_arena.sql` creates the `arena_*` tables with RLS on and no client
  policies. The browser never touches the tables; every call goes through the `arena` Edge Function.
- **Auth:** anonymous sign-ins must be enabled (Authentication → Sign In / Providers). The function validates
  sessions itself, so gateway JWT verification is off (`verify_jwt = false`, `--no-verify-jwt`).
- **Deploy via GitHub Actions** (`.github/workflows/deploy-arena.yml`):
  - Runs `npm test`, then `supabase functions deploy arena`, then a smoke test (CORS preflight plus an
    unauthenticated call that must return an error).
  - Triggers on pushes to `main` that touch server code, or manually from the Actions tab (once the workflow
    exists on `main`).
  - One-time setup: add the repository secret **`SUPABASE_ACCESS_TOKEN`**, a personal access token from
    https://supabase.com/dashboard/account/tokens. Optionally set the variable `SUPABASE_PROJECT_REF`.
  - The workflow does **not** run migrations. Apply schema changes with `supabase db push` or the SQL Editor.
- **Deploy via CLI:** `supabase link --project-ref xsjgycaytzqtnvesowdh && supabase db push && npm run sync && supabase functions deploy arena --no-verify-jwt`
- **Deploy via the dashboard:** paste `dist/arena-function.ts` (from `npm run bundle`) into Edge Functions →
  `arena`, then turn off "Verify JWT with legacy secret".

### 7.3 Tactics online duels
These use Supabase **Realtime only**: a broadcast + presence channel per room (`wwt-room-CODE`) and a lobby channel
(`wwt-lobby`). There are no tables and no function. Peers exchange numbered commands, gaps are repaired from the
other peer's log, and there is a 90 s turn clock and a 60 s reconnect window. Play is trust-based: both clients
validate every command and report a desync. They use the same `config.js` URL and key.

### 7.4 Hosting the site
`public/` is fully static. Any static host works (GitHub Pages, Netlify, Cloudflare Pages, Supabase Storage). No
build is needed. The host must serve `.js` as JavaScript (for ES modules) and allow `.glb` files. The meshopt decoder is plain JS with no separate `.wasm` file.

## 8. Working conventions
- Keep the simulation and engine modules (`sim.js`, `battle.js`, `grid.js`, `server-core.js`, `economy.js`,
  `stronghold.js`, `chess.js`) **pure**: no DOM, no Three.js, no `Math.random()` (use the seeded RNG). The Node
  tests and the server depend on that.
- After editing a file listed in `scripts/sync-shared.mjs`, run `npm run sync` and commit the `_shared` copies too.
- After changing models, run `npm run pack` and commit `public/assets/packs/`.
- Dispose GPU resources you create (geometries, materials, cloned textures) when a game or battle ends. The games
  start several sessions per page load, and earlier leaks were real.
- Phone layouts are driven by CSS media queries in each game's stylesheet. Check 390×844 after HUD changes.
  Tactics' camera framing measures the HUD, so moving a panel is fine, but adding a new one may need it added to
  the list in `View.fitBoard`.

## 9. Known limitations
- **Live Supabase is untested from the dev container**, which cannot reach `*.supabase.co`. The function and store
  are covered by an in-memory fake of supabase-js, but the deployed function has not been smoke-tested by us. The
  live function predates the latest server fixes (settle-once claim, conditional updates), so **redeploy it**
  (§7.2) and run the workflow's smoke test.
- **Real-device frame rates are unverified.** Performance was measured in headless Chromium with a software
  renderer (draw calls, heap, requests). Try a mid-range Android phone and an integrated-GPU laptop.
- **Online duels are trust-based.** A modified client can't make illegal moves, but it can stall or disconnect
  (handled by the clocks). There is no server referee or ranking for duels.
- **No attack or sit animations** exist in the free Adventurers pack. Attacks are procedural lunges layered on
  `Use_Item`/`Throw`, and the potion bottle is a procedural mesh.
- **Auto end turn** skips leftover moves once every hero has used its action. That is the chosen design. Players
  who want to reposition after attacking can untick the toggle or select a hero during the 0.9 s pause.
- The Playwright verification scripts live outside the repo. Commit a small `tests/e2e/` suite if regressions
  appear.
